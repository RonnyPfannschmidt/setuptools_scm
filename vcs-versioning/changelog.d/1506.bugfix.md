A shallow clone that still reaches a matching tag no longer warns about being
shallow, and no longer triggers a needless `git fetch --unshallow` under
`fetch_on_shallow`: shallowness is only reported when it is why no tag was
found. This generalises the `HEAD`-is-exactly-a-tag carve-out from #1241,
which only covered distance 0.

Shallowness is now detected with `git rev-parse --is-shallow-repository`
rather than by looking for `.git/shallow`, so it is also correct in worktrees
and submodules, where `.git` is a file.
