Add `on.missing_tag`, `on.shallow` and `on.missing_submodules` to say what
should happen when the repository is not in the shape we need. By default a
repository with no matching version tag now warns that its version was
invented rather than reported, instead of silently producing `0.1.dev1+g...`.

Unlike the `scm.git.pre_parse` hook they replace, these compose: failing on a
shallow clone *and* on a missing tag is now expressible.

`ScmVersion.tag_found` exposes the same information to `version_scheme`
implementations, which previously had to sniff the invented tag.

`on.shallow` now also governs `scm.git.distance_scope`, which previously raised
a hard error of its own. A truncated history makes a path-restricted count
wrong even when a tag *is* found, so it is answered before describe rather than
after: `"fetch"` unshallows so the count can be answered properly, and leaving
the setting at its default keeps the hard failure.
